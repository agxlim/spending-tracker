# spending-tracker

Tech 42 Assignment 3

A web app that keeps your monthly spending under one total budget. It turns the budget into a daily **safe to spend** number, rewards under-pace days with streaks, and shows simple insights. See [`PRD.md`](PRD.md) for the full spec.

**Stack:** Next.js 16 (App Router) + TypeScript, Tailwind CSS, Recharts, Supabase (Postgres + Auth), Zod, Vitest, Playwright.

## Running locally

You need Node.js 22+ and Docker (for local Supabase).

```bash
npm install
npm run db:start            # starts local Supabase and applies supabase/migrations
cp .env.example .env.local  # then fill in the two values below
npm run dev                 # http://localhost:3000
```

Fill `.env.local` from `npx supabase status`:

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `API URL` (usually `http://127.0.0.1:54321`) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `anon key` / `Publishable key` |

Only the public anon key is used. Row-Level Security limits it to the signed-in user's rows; the service-role key is never needed.

**Signing in locally:** local Supabase doesn't send real email. Open the test inbox at <http://127.0.0.1:54324> to click your magic link.

## Tests

```bash
npm test             # unit tests (budget math, streaks, insights, CSV parsing)
npm run test:e2e     # Playwright smoke test; needs `npm run db:start` running
npm run typecheck
npm run lint
```

The smoke test signs up through the local test inbox, sets a budget, adds spending and checks that safe-to-spend changes. Before the first run, install its browser with `npx playwright install chromium`.

## Project layout

| Path | What's there |
|---|---|
| `src/lib/` | Pure logic: dates, money (integer cents), budget, streaks, insights, CSV import |
| `src/lib/queries.ts` | Data loading as the signed-in user |
| `src/app/(app)/` | Signed-in pages: dashboard, transactions, import, insights, settings |
| `src/app/login`, `src/app/onboarding`, `src/app/auth/callback` | Sign-in and first-run setup |
| `src/proxy.ts` | Refreshes the session and sends signed-out visitors to `/login` |
| `supabase/migrations/` | Schema, RLS policies, import and account-deletion functions |
| `tests/unit/`, `e2e/` | Vitest unit tests and the Playwright smoke test |

## Deploying

1. Create a Supabase project and run the migration: `npx supabase link` then `npx supabase db push`.
2. In Supabase → Authentication → URL Configuration, set the Site URL to your Vercel URL and add `https://<your-app>/auth/callback` to the redirect URLs.
3. Import the repo in Vercel and set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

Both free tiers are enough.

## Notes

- **Database types** in `src/lib/supabase/database.types.ts` were written by hand to match the migration. With Supabase running, regenerate them with `npx supabase gen types typescript --local > src/lib/supabase/database.types.ts`.
- **UI components** in `src/components/ui/` follow shadcn/ui's API and styling but were written by hand; the shadcn registry wasn't reachable when they were built.
- **App icons** are generated by `node scripts/generate-icons.mjs public/icons src/app`.
